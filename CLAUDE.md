## Commands (PowerShell, repo root)

```powershell
uv sync                                                            # .venv from uv.lock, dev group (pytest, PyInstaller, httpx2) included
uv run python -m riviu                                             # web app on http://127.0.0.1:1231 (`python app.py` is a shim for the same)
uv run pytest -q tests                                             # full suite; always pass `tests` so scratch copies under output/ are not collected
uv run pytest -q tests/test_threads.py::test_name                  # single test
uv run pytest -q tests -k "proxy and threads"                      # by keyword
node --check riviu/web/static/app.js                               # JS syntax check (also run in CI)
uv lock --check                                                    # uv.lock matches pyproject.toml (also run in CI)
npm run desktop:dev                                                # build PyInstaller sidecar, then `tauri dev`
npm run desktop:build                                              # sidecar + installers (needs Rust toolchain)
uv run python -m riviu.server_mode hash-password                   # scrypt hash for server mode's shared password (reads stdin / prompts)
docker compose -f deploy/server/compose.yaml build                 # server-mode image (see deploy/server/README.md)
uv run python tools/make_guide_screenshots.py                     # regenerate usage-guide screenshots (riviu/web/static/guide/) after UI changes
git diff --check
```

**Dependencies.** `pyproject.toml` declares them (runtime in `dependencies`, test and build tools in the `dev` group; `[tool.uv] package = false`, so the project itself is never installed and runs from the repo root) and `uv.lock` pins them for every CI target. After changing a dependency, run `uv lock` and regenerate the pip fallback with `uv export --format requirements.txt --no-dev --locked -o requirements.txt`; `tests/test_dependency_lock.py` fails if `requirements.txt` drifts from the lock. End users never run uv by hand: `setup.bat`, `capnhat.bat` and `Khoidong.bat` call `thuvien.bat`, which installs uv if needed and runs `uv sync --locked --no-dev`, or falls back to pip with `requirements.txt`. `capnhat.bat` replaces itself through `git reset --hard` while cmd is still reading it: read the comments above its `:` landing zone and `OLD_CAPNHAT_RESUME_OFFSETS` in `tests/test_batch_scripts.py` before editing it.

Opt-in tests are skipped unless you set env vars: `THREADS_LIVE_URL`, `THREADS_SHARE_URL` (live Threads scans), and `RIVIU_TEST_URL` (UI against a running server). Frontend regression tests in `tests/test_ui_review_fixes.py` and related files run `riviu/web/static/app.js` inside a Node `vm` harness with stubbed DOM, `fetch`, and `WebSocket`. The harness turns the source-row markup that app.js renders into the stub elements, and it fails if any `PLATFORMS[*].dom` id was not rendered. They skip if `node` is not on PATH. The DPAPI tests run only on Windows.

Riviu Reports ships as the web app on the server (report.taskscatt.click, deployed with `deploy/server/update.sh`); desktop installers are no longer published. `.github/workflows/checks.yml` runs `uv lock --check`, pytest (`pyproject.toml` sets `testpaths = ["tests"]` and puts the repo root on `sys.path`) and `node --check` on pull requests into `main` and on every push to `main`; it publishes nothing. `.github/workflows/desktop-release.yml` still builds and publishes installers, but only when run by hand (`workflow_dispatch`). Merge only when the checks are green.

## Architecture

**One local FastAPI process, two ways to run it.** All Python code is the `riviu` package. `riviu/app.py` builds the HTTP/WebSocket server: the FastAPI `app`, its middleware and static mount, and the routers from `riviu/api/` (one per concern: `auth` (server-mode login), `pages`, `sources`, `google`, `proxy`, `export`, `threads_session`, `scan` for `/ws`). It re-exports their public names, and forwards reads and writes of the mutable state names (`EXCEL_DIR`, `CURRENT_*`, `manager`, `SCRAPE_TASK`, `SOURCE_BUSY`, ...) to their owning module, so `riviu.app.<name>` keeps working. Partner Excel reports and Google push rows are built in `riviu/reports.py`. In source mode you run `python -m riviu` (`riviu/__main__.py`; `Khoidong.bat` does this, and the root `app.py` shim does the same for old habits). In desktop mode, Tauri (`src-tauri/src/lib.rs`) launches the PyInstaller-built sidecar `riviu-server` (`riviu/desktop_server.py`, entry script `desktop/sidecar_entry.py`, built by `desktop/build_sidecar.py`). On Windows it is a one-folder build shipped as bundle resources and started from the resource dir. On macOS/Linux it is a one-file `externalBin` (see `docs/desktop-release.md`). Tauri passes `RIVIU_PORT`, `RIVIU_SHUTDOWN_TOKEN`, and `RIVIU_DATA_DIR` (the OS app-data dir), then loads the UI from loopback. `riviu/desktop_server.py` adds token-protected `/_desktop/prepare-update|cancel-update|shutdown` routes. The updater refuses to install while a scan or source operation is running. Chromium is bundled into the sidecar (`PLAYWRIGHT_BROWSERS_PATH=0`, packaged process only).

**Paths.** `riviu/paths.py` owns both locations. Web resources live in `riviu/web/` (`templates/`, `static/`, `logo.png`) under the repo, or under `sys._MEIPASS` when frozen (the sidecar build adds `riviu/web` at that same relative path); `app.APP_RESOURCE_DIR` is that `riviu/web` dir. `app.EXCEL_DIR` (`paths.data_dir()`) comes from `RIVIU_DATA_DIR`, falling back to the **repo root** in source mode (existing installs keep their data there; do not move it into the package) and the bundle root when frozen. It holds the user data: `data/` workbooks, `google_oauth_client.json` and token, `google_sheet_sources.json`, proxy list, scrape history, `threads_scan_history.json`, and the encrypted Threads cookie store. Tests isolate state by pointing these at `tmp_path` or monkeypatching them.

**Local API protection.** The `protect_local_api` middleware (`riviu/api/security.py`) rejects non-loopback Host/Origin headers and cross-site fetches. Every route except `GET /`, static assets, and `/_desktop/*` requires a per-process session cookie that is set when `/` is loaded. Ad-hoc HTTP calls (curl, test clients) must load `/` first or they get 403.

**Server mode (opt-in, `RIVIU_SERVER_MODE=1`).** A third way to run the same app: hosted on a Linux server in Docker behind nginx (TLS at nginx) for a small team with per-person accounts and one data dir; see `docs/server-mode.md` and `deploy/server/`. `riviu/server_mode.py` reads and validates the config (`RIVIU_PUBLIC_ORIGIN`, `RIVIU_PASSWORD_HASH[_FILE]`, `RIVIU_SECRET_KEY_FILE`, `RIVIU_HOST/PORT`, `RIVIU_FORWARDED_ALLOW_IPS`) into `server_mode.ACTIVE`; `riviu.app` activates it at import and refuses to start (`ServerModeError`) when a setting is missing. `ACTIVE is None` means desktop/source mode, and every server-mode branch keys on it, so those modes are unchanged; tests enable it by monkeypatching `server_mode.ACTIVE` (`tests/test_server_mode.py`). In server mode `protect_local_api` delegates to `protect_server_api`: Host/Origin must match the public origin (or loopback, for the container health check), `/_desktop/*` is 404, and everything except `/login`, `/logout`, `/auth-status`, `/healthz` and the assets the login page loads (`SERVER_PUBLIC_ASSET_PATHS`) needs the `__Host-riviu_auth` login cookie (server-side random token, SHA-256 persisted in `data/server_sessions.json`, bound to the shared password hash and to the account's own password hash, so a changed or removed account loses its sessions). Accounts live in `riviu/server_users.py` (`data/server_users.json`, scrypt hashes, roles `admin` and `viewer`, managed with `python -m riviu.server_mode add-user|set-password|set-role|remove-user|list-users`); until the first account exists the shared `RIVIU_PASSWORD_HASH` logs in as an admin, afterwards logins need a username. A `viewer` may only call the read-only routes in `security.VIEWER_ROUTES` (browse sheets, partner list, export partner reports) plus assets; everything else answers 403, and `/ws` refuses its `start`/`cancel` (`security.is_admin`). `/auth-status` returns `{authenticated, user: {username, role}}`. HTML requests redirect to `/login`, API calls get 401, `/ws` closes. `riviu/api/auth.py` owns the login routes and the per-IP failed-login limit. The Threads cookie store becomes `EncryptedFileStore` (AES-GCM, key from `RIVIU_SECRET_KEY_FILE`) instead of DPAPI/keyring, and `/google-oauth-login` returns a consent URL for the paste-back flow (`/google-oauth-complete`, state + PKCE checked) instead of opening a browser on the host.

**Scan flow.** The UI (`riviu/web/templates/index.html` + the single file `riviu/web/static/app.js`) starts a scan over the `/ws` WebSocket. `prepare_scan_start` validates the payload against the workbook named by its `file_id` (not the last `/select-file`) and builds a `scan_options(...)` dict. `riviu/scan_state.py` holds one global `SCRAPE_TASK` and the `SOURCE_BUSY`/`DESKTOP_UPDATE_PENDING` gates (`scan_running()`, `source_mutation_blocked()`, `source_operation()`), so only one scan runs at a time, and `run_scraper_safely(target_path, options)` in `riviu/scan_service.py` dispatches through `SCAN_RUNNERS[platform]`:
- `tiktok` → `riviu.platforms.tiktok.run_scraper` (Request / Browser / Hybrid modes, worker pool, retries, optional result sheet, sheet total rows). `riviu/platforms/tiktok/` is a package: pure page parsing (`parsing.py`), the HTTP limiter (`throttle.py`), page fetch and oEmbed gone check (`fetch_html.py`, `gone.py`), channel names (`channels.py`), per-link scraping (`fetch_request.py`, `fetch_browser.py`), worker loops (`workers.py`), browser lifecycle (`lifecycle.py`), workbook writes and history (`workbook_io.py`, `history.py`), UI payloads (`progress.py`) and the run itself (`runner.py`). `__init__.py` re-exports the public names, but tests must patch a seam on the submodule that defines it (`monkeypatch.setattr(tiktok.fetch_html, "fetch_tiktok_html", ...)`), because siblings call it through that module.
- `threads` → `riviu.platforms.threads.run_threads_scraper`. When a cookie session is enabled, `riviu.platforms.threads_session.ThreadsSession` supplies verified cookies plus a fixed proxy route. Only a `SessionError` invalidates the session; other failures leave it valid.

A failed Google push after a saved scan is logged as a warning, not a failed scan.

**Adding a platform.** Platform differences live in tables, not `if threads` branches: `PLATFORMS` in `riviu/workbook/platforms.py` (`PlatformSpec`: report columns, link normalizer/matcher, channel display, video-link highlighting, whether partners without links of that platform are listed, file and Google-tab naming), `scan_service.SCAN_RUNNERS` and `scan_service.PROXY_VALIDATORS` (re-exported as `app.*`; a test asserts these cover the same keys), and the `PLATFORMS` object at the top of `riviu/web/static/app.js` (plus the icon in `riviu/web/static/platform-icons/`). A new scanner module goes in `riviu/platforms/`. `riviu/web/templates/index.html` needs no edits: the platform bar and the source-drawer rows (file label, Google link, sync, sheet select, push) are rendered from `PLATFORMS` by `renderPlatformBar()` / `renderPlatformSourceRows()` into `#platformBar` and `#platformSourceRows`. Each entry's `dom` map names the element ids those rows get, and `sourceControls(platform)` looks them up by these ids. TikTok keeps its legacy ids (`googleSheetUrlInput`, `pushGoogleBtn`, ...), so the ids must stay unique across entries.

**Usage guide.** The header's help button (`#guideButton`, all modes) opens `#guideModal`, whose steps live in `riviu/web/templates/guide.html` with screenshots in `riviu/web/static/guide/`. The callout numbers in the text match the screenshots; when the UI changes, edit both and rerun `tools/make_guide_screenshots.py`, which drives a local server-mode instance with synthetic workbooks and a fake TikTok fetch (no network scans).

Scrapers report progress through the `ConnectionManager` (`manager`) via `broadcast_log/status/data/duplicates`. Every message carries the run context (`runId`, `platform`, `fileId`, `sheetName`), and the frontend uses it to drop stale events. Results are written into the workbook in place using atomic saves (temp file + replace). After a scan, results can optionally be pushed to a new tab in the source Google Sheet.

**Module ownership.** Keep platform extraction (`riviu/platforms/`) separate from workbook and transport code. Import package modules absolutely (`from riviu import app`, `from riviu.platforms import tiktok`), and patch them by their package path in tests (`patch("riviu.reports.ExcelImage")`); a bare `import app` would load the root shim, not the server module.
- `riviu/server_context.py`: `EXCEL_DIR`, `APP_RESOURCE_DIR`, the legacy current selection (`CURRENT_SELECTED_FILE/SHEET`, `CURRENT_SCAN_SHEET`, used only when a request omits `file_id`), `GOOGLE_IO_LOCK`/`google_io`, `complete_blocking` and the Threads session singleton. `riviu/source_files.py` resolves a request's `file_id` + `platform` to a workbook (`resolve_source_file`) and publishes uploads/syncs without overwriting. Routers and the scan service read this state through the module object (`context.EXCEL_DIR`), never `from ... import EXCEL_DIR`, so monkeypatching `riviu.app.EXCEL_DIR` reaches them. To stub a function a route calls, patch it where that route looks it up (`riviu.api.google.push_rows_to_new_sheet`, `riviu.scan_service.run_scraper`, `riviu.source_files.file_entries`); patching the re-export on `riviu.app` has no effect.
- `riviu/workbook/`: workbook logic, one module per concern: `constants` (column/sheet names, `COLUMN_ALIASES`, the hidden internal columns `__TTBD_*` and `__THREADS_SCAN_STATUS`), `text`, `dates`, `links`, `channels`, `platforms` (the platform registry), `columns` (column lookup), `partners` (partner parsing), `naming` (result/summary sheet naming, timestamp regex), `snapshot` (`WorkbookSnapshot` and `WORKBOOK_READ_CACHE`), `atomic`, `files`, `google_registry` / `google_fetch` (Google-sheet file registry, title and export download), `catalog` (workbook list), `report_rows`, `preview` (preview/summary dashboards), `summary` (the "Tổng kết" tab) and `highlight` (row fills). `riviu/workbook_utils.py` is a compatibility facade that re-exports the same objects; existing imports from it keep working, but patch a name in the module that looks it up. Both scanners and the reports find columns through `worksheet_find_column_index` / `worksheet_ensure_column` / `COLUMN_ALIASES` (matching is case- and diacritic-insensitive). A scanner with its own header matcher appends duplicate columns that the reports never read. Write workbooks and JSON state through `save_workbook_atomic` / `write_json_atomic`. Their hidden `.riviu-*.tmp` temp files never appear in the workbook list.
- `riviu/reports.py`: partner Excel reports (`build_partner_report`: logo/banner, platform icon, totals, row fills), the export payload (`build_export_payload`: snapshot copy, single `.xlsx` or `.zip` of partner reports), and the Google push rows (`build_google_push_rows`). Pure workbook logic: it never imports `riviu.app` and holds no FastAPI, scan state, locks or WebSocket code. Tests patch report internals (`build_workbook_rows`, `format_filename_datetime`, `ExcelImage`) on `reports`, not `app`.
- `riviu/proxy_utils.py`: proxy list parsing and storage, plus HTTP/SOCKS transports. Both platforms use it.
- `riviu/google_sheets_sync.py`: OAuth client upload and login, authenticated download, and pushing rows to a new sheet. Calls go through `google_io` / `GOOGLE_IO_LOCK`. The exception is the interactive `authorize_google` browser login, which has a timeout and runs only from `/google-oauth-login` outside that lock. Background pushes and syncs raise `GoogleLoginRequired` instead of opening a browser.
- `riviu/platforms/threads_session.py`: cookie normalization (Cookie-Editor JSON), OS secure store (DPAPI on Windows, keyring elsewhere, no plaintext fallback), and session verification with a redirect-guarded navigation.

**Platform sources.** TikTok and Threads each keep their own source: file, sheet, and Google link, persisted through `/source-preferences`. API calls pass an explicit `file_id` + `platform`, and code must never fall back to the other platform's workbook.

## Domain invariants (easy to break)

- Missing or unavailable metrics stay **blank/None** on both platforms, in the workbook, previews, partner reports and Google pushes. Write `0` only for a confirmed zero. When scraping fails, keep the existing cell values, with two deliberate exceptions where the old numbers are cleared to blank:
  - TikTok hidden stats, and TikTok posts **confirmed** gone (`riviu.platforms.tiktok.should_clear_stale_metrics`). The status column explains these. TikTok intermittently answers "item not found" (statusCode 10204, a rendered "unavailable" page, or HTTP 404/410) for live posts, so such a page is only a suspicion: it is retried like any failure (and sent to the browser fallback in Hybrid), and it clears numbers only when TikTok's oEmbed endpoint also rejects the post id (`riviu.platforms.tiktok.confirm_tiktok_post_gone`). Unconfirmed, it keeps the old values.
  - Threads unconfirmed views, per `docs/threads-scanning.md`.

  Totals (partner reports, Google pushes, previews, the "Tổng kết" sheet and dashboard) sum the known values and stay blank only when nothing in that column is known.
- Threads partner reports and Google pushes use the TikTok layout and rules: the same 8 columns with REPOST in the LƯỢT LƯU slot, no status column (the scan status stays in the hidden `__THREADS_SCAN_STATUS` workbook column), the same failed-channel and min-views filters, and a blank TÊN KÊNH shown as `@username` from the post URL.
- Threads never uses numbers from captions, suggested posts, or redirected Home pages. It never rotates proxies to get around 403/429/geoblocks, and never falls back to direct/anonymous connections when the chosen route fails. Logs must not contain proxy credentials or cookies.
- `docs/threads-scanning.md` (Vietnamese) is the authoritative spec for Threads modes, statuses, cookies, and proxy routing. `docs/platform-branding.md` specifies the Excel export layout (logo A1, header row 3, platform icon at H2 on both platforms). `docs/desktop-release.md` covers release secrets and the updater. `docs/server-mode.md` specifies server mode (login, sessions, cookie store, Google paste-back) and `deploy/server/README.md` its deployment. Dated review reports, plans and specs are history in `docs/archive/`, not current specs.
- User-facing strings are Vietnamese. Keep UTF-8.
